PRL Wallet privacy / 隐私说明

Updated: 2026-10-21

The wallet encrypts recovery phrases and pending signed transactions locally. The unlock key is held in trusted extension session storage and cleared on lock. Recovery phrases, private keys and passwords are never sent to servers.

Mainnet chain queries go first to Pearl Hub’s own Blockbook index at pearlhub.net/node, and to Pearl’s official Blockbook when ours is unavailable or behind; testnet uses only the official testnet Blockbook. These queries carry public account keys, addresses and transaction IDs. An explicitly confirmed payment sends the signed transaction to both mainnet indexes. Rebroadcast, in a transaction’s details, sends the unconfirmed transaction the indexes already hold back to the network.

The pearlhub.net permission covers our own index (above), public market requests without wallet identity or cookies, and optional email account login and contact sync. The identity permission opens the shared sign-in page and receives a one-use PKCE callback; it does not read your Google or Microsoft account.

本机加密保存助记词与待确认交易；解锁密钥只存于可信扩展会话，锁定后清除。密码、助记词和私钥不会发给服务器。主网链上查询先发给 Pearl Hub 自建的 Blockbook 索引（pearlhub.net/node），它不可用或数据落后时改用 Pearl 官方 Blockbook；测试网只用官方测试网 Blockbook。查询会收到公开账户公钥、地址和交易编号；用户确认付款时，已签名交易同时发给两边；在交易详情点「重新广播」时，把索引已有的那笔未确认交易再次发往网络。

pearlhub.net 权限用于自建索引（见上）、公开行情及可选邮箱账号登录、通讯录同步。identity 权限用于打开统一登录页并接收一次性授权回调，不读取 Google 或 Microsoft 账号。

Contact names, public addresses and notes remain unencrypted in trusted local extension storage. Optional account sync stores email, public contacts and device metadata on Cloudflare. Configuration is encrypted at rest; the server can read it. Account credentials stay in trusted local extension storage and are independent of wallet unlock. Sign-out restores guest contacts. Account settings export and deletion are available on the account page. No Chrome account sync is used.

Only after a user clicks a web link is the selected public mainnet address placed in the URL fragment (#workers or #wallet). The initial HTTP request does not contain that fragment. The web application then receives the prefilled public address and may query it after loading. Optional donations and change consolidation use the same preview and password-confirmed local signing flow. Consolidation sends only confirmed change to your own primary address.

通讯录名称、公开地址和备注以明文存于可信插件本机存储。可选邮箱同步会在 Cloudflare 保存邮箱、公开联系人及设备信息；云端配置加密存储，服务器可以读取。账号登录凭据存于可信插件本机存储，与钱包解锁独立。退出账号恢复未登录时的联系人。账号页可导出配置、注销账号。数据不通过 Chrome 账号同步。点击网页链接才会将主网公开地址交给网页预填和查询；捐赠与找零归集仍需预览及密码确认。

NOCK (Nockchain): the same recovery phrase also opens a NOCK address, derived on this device. Only after you open NOCK does the extension ask NockBox’s public Nockchain node (rpc.nockbox.org) for that address’s balance; the requests carry identifiers derived from the address. NOCK transactions you confirm with your password are signed here and broadcast to that node. If that node cannot be reached, the NOCK page offers the node the official Nockchain wallet uses by default (216.158.95.10); it uses plain, unencrypted HTTP, so others on the network path can see those requests. Only if you allow it (an optional site permission Chrome asks you to confirm) does the extension also send the same requests and broadcasts there. The NOCK price is requested from CoinGecko without any address or identity. The NOCK address and its history are stored unencrypted in local extension storage, like contacts, and are deleted with the wallet.

NOCK（Nockchain）：同一组助记词也对应一个 NOCK 地址，在本机派生。只有在你打开 NOCK 后，插件才向 NockBox 的公共 Nockchain 节点（rpc.nockbox.org）查询这个地址的余额，请求里带有由地址推出的标识；你用密码确认的 NOCK 交易在本机签名后广播给该节点。该节点连不上时，NOCK 页会提出改用 Nockchain 官方钱包默认使用的节点（216.158.95.10）；它走未加密的明文 HTTP，网络路径上的其他人能看到这些请求。只有你允许后（Chrome 会请你确认一项可选的网站权限），插件才会把同样的查询和广播也发给它。NOCK 币价向 CoinGecko 查询，不带地址或身份信息。NOCK 地址和记录与通讯录一样以明文存于插件本机存储，移除钱包时一并删除。

No analytics, advertising, tracking, content scripts or remote executable code. Browser/network infrastructure can observe request IP addresses. Browser removal deletes local wallet data; retain your offline backup.
